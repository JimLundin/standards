# Dead code that tests alone use

Question: which tools can find unused functions, methods, fields, variants, exports and types in each language, without counting a use from test code as a use, and what would we have to build? Researched 2026-11-28. Probes ran on knip 6.48.0, clippy 1.100.0 and tsc 7.0.2.

## Python

Vulture 2.16 (released 2026-03-25) reads only the paths it's given, and it matches names across the whole program, ignoring scopes ([README](https://github.com/jendrikseipp/vulture)). Today `python/check.sh` passes it every tracked `.py` file, so a use in a test counts.

The fix is a second pass over the files outside the tests. That pass reports anything only tests use, and the current pass still catches dead helpers inside the tests. Framework entry points go in a whitelist file or `--ignore-decorators`.

Limits:

- Any `x.foo` anywhere keeps every attribute named `foo` alive.
- Dynamic uses, such as `getattr`, come out as false positives.

Alternatives:

- [deadcode](https://github.com/albertas/deadcode) 2.7.0 works on the same model. It tells same-named definitions apart only when a use resolves through an import, and attribute loads still keep every definition of that name alive.
- [skylos](https://github.com/duriantaco/skylos) 5.8.0 only stops test functions from being reported. Whether it discounts uses from tests is unconfirmed.
- basedpyright's `reportUnusedFunction` covers underscore-private names only ([config docs](https://docs.basedpyright.com/latest/configuration/config-files/)).

## TypeScript

knip's [production mode](https://knip.dev/features/production-mode) leaves the tests out of the analysis. Its production files are marked with a `!` suffix on `entry` and `project`, and it runs with `--production` in addition to the default run, not instead of it.

In the probe, `--production` reported an export, an exported type and an enum member that only a test used, and the default run reported none of them.

knip 6.0.0 dropped class-member checks along with TypeScript's JS language service ([blog](https://knip.dev/blog/knip-v6)). It never covered interface properties or the properties of exported object literals, and the probe confirmed it misses all three.

`noUnusedLocals` flags only `private` and `#` members.

tsr is archived and points to knip ([repo](https://github.com/line/tsr)), and ts-prune's last release was in 2022.

What we'd build: a member check that asks the tsgo language server for the references to each public member and property, and drops the references from test files. Whether tsgo serves `references` well enough is unconfirmed.

## Rust

With `--all-targets`, cargo also checks the library without `cfg(test)` ([cargo check](https://doc.rust-lang.org/cargo/commands/cargo-check.html)). So `dead_code` under `warnings = "deny"` already fails on private items that only tests use. The probe showed this for fns, struct fields, enum variants and the methods of private traits.

The gap: rustc seeds its liveness worklist with every item reachable from the crate root ([dead.rs](https://github.com/rust-lang/rust/blob/1.100.0/compiler/rustc_passes/src/dead.rs#L1042)). So a reachable `pub` fn, field, variant or trait method is never reported. In the probe this held for a binary's root too.

None of these close the gap:

- `unreachable_pub` adds nothing beyond `dead_code`, and its `pub(crate)` suggestion conflicts with the denied `redundant_pub_crate`.
- cargo-machete, cargo-shear and cargo-udeps check dependencies only.
- [warnalyzer](https://github.com/est31/warnalyzer) targets this gap, but it was last changed in 2024 and calls itself early.

What we'd build:

1. List each workspace library's public items with their spans from the rustdoc JSON that `rust-api` already reads.
2. Index the workspace with `rust-analyzer scip`, with `cfg.setTest` set to false ([config](https://rust-analyzer.github.io/book/configuration.html)), so `cfg(test)` code isn't indexed.
3. Drop the references in `tests/` and `benches/`.
4. Report each public item with no reference outside its own crate, unless it's part of a published API.

How reliably rust-analyzer resolves uses generated by macros is unconfirmed.

## What this decides

- **Python:** adopt vulture's second pass now.
- **TypeScript:** adopt knip's production run now.
- **Rust:** private dead code is already covered.
- **To build:** a check for unused pub items across the Rust workspace, and a check for unused public members and properties in TypeScript. Both rest on a language server's references with the tests left out.
